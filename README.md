# 상장사 재무·시장 시계열 아카이브 — 읽는 법

이 저장소는 **한국·미국 상장기업의 분기별 재무제표와 주식 시장 데이터를 한 표에 모아 쌓아 둔 것**입니다.
숫자를 모으는 과정과 판단을 전부 글로 남겨 두었는데, 그 기록이 `*-log.md` 파일들입니다.

이 문서는 **그 로그를 어떻게 읽는지** 설명합니다. 프로그램을 돌리거나 코드를 볼 필요는 없습니다.

> 이 자료는 공시 원문을 그대로 옮겨 쌓은 기록입니다. 투자 판단이나 추천이 아니며,
> 앞으로의 실적이나 주가를 예측하는 내용은 들어 있지 않습니다.

---

## 1. 먼저 알아둘 것: "라운드"와 "부서"

작업은 **라운드** 단위로 진행합니다. 한 라운드에서 기업 20곳을 골라 데이터를 채웁니다.
2026-09-21 기준 국내 5라운드(51개사), 미국 16라운드(300개사)까지 끝났습니다.

각 라운드는 **가상의 부서들이 순서대로 일을 넘기는 방식**으로 돌아갑니다.
로그의 절 번호가 곧 이 순서라, 번호만 봐도 어느 단계 이야기인지 알 수 있습니다.

| 절 | 부서 | 하는 일 |
|---|---|---|
| 1 | 시장조사팀 | 이번에 추가할 후보 기업을 찾고, 자료를 실제로 받을 수 있는지 확인 |
| 2 | 기획 1팀 | 후보 중 시가총액 순으로 대상 20곳과 수집 항목 확정 |
| 3 | 브랜드 검수팀(QA) | 그 목록을 검사해 통과(O)/반려(X) 판정 |
| 4 | 기획 2팀 | 실제 수집 — 여기서 데이터셋 파일이 만들어짐 |
| 5~ | 성과리뷰팀 | 채운 데이터의 이상치·결측 점검 |
| 그 뒤 | (상황별) | 진단, 계산값 재확인, 회귀 검사 등 |

초기 국내 라운드(1~3)는 절 번호 없이 제목만 있는 경우가 있는데, 순서는 같습니다.

## 2. 어떤 파일을 어디서 보나

```
coverage-log.md      ← 전체 현황과 확정된 규칙. 여기서 시작하세요
README.md            ← 지금 이 문서

kr/                  국내 트랙
  logs/              라운드별 상세 기록 (round1-log.md ~ round5-log.md)
  data/              데이터셋 (round1-dataset.csv ~)
us/                  미국 트랙
  logs/              us-round1-log.md ~ us-round16-log.md
  data/              us-round1-dataset.csv ~
```

**읽는 순서를 하나만 고르라면: `coverage-log.md` → 관심 있는 라운드 로그.**

- `coverage-log.md` = **현재 상태 요약 + 확정된 규칙**. 어떤 기업이 얼마나 채워졌는지, 왜 그렇게 정했는지가 모여 있습니다. 길지만 목차 역할을 합니다.
- `kr/logs/`·`us/logs/`의 라운드 로그 = **그때 무슨 일이 있었는지 상세 기록**. 판단 근거와 실패 사례가 여기 있습니다.

## 3. `coverage-log.md` 읽는 법

크게 네 덩어리입니다.

### 3-1. 커버리지 요약 표

"어느 기업이 얼마나 채워졌나"를 보여줍니다. 한 기업당 **330칸**이 기본입니다
(30개 분기 × 11개 항목 = 330).

| 열 | 뜻 |
|---|---|
| 수집 분기 범위 | 언제부터 언제까지 받았는지. `2019Q1~2026Q2 (30)`이면 30개 분기 전부 |
| **값 있는 칸** | 실제 숫자가 들어간 칸 수 |
| **데이터 없음** | 원래부터 존재할 수 없는 칸 (상장 전, 회사 설립 전 등) |
| **미확인** | 있을 법한데 못 얻은 칸 |

**"데이터 없음"과 "미확인"의 차이가 이 저장소에서 가장 중요한 구분입니다.**

- **데이터 없음** = 없는 게 맞습니다. 2019년에 상장하지 않은 회사의 2019년 주가 같은 것.
- **미확인** = 있어야 할 것 같은데 확보하지 못했습니다. 왜 못 얻었는지 항상 출처 열에 적어 둡니다.

빈칸은 절대 두지 않습니다. 모르면 "모른다"고 적습니다.

### 3-2. 확정된 규칙

"값을 어떻게 만드는가"를 정해 둔 부분입니다. 일반 독자에게 가장 쓸모 있는 두 가지:

- **분기 값 만드는 법** — 회사는 보통 1~3분기를 "3개월 치"로 공시하지만 4분기는 따로 안 냅니다.
  그래서 **4분기 = 연간 − 1~3분기 누적**으로 계산합니다. 영업활동현금흐름은 1분기만 공시라
  **2~4분기 = 이번 누적 − 직전 누적**입니다. 이렇게 만든 값은 원본 숫자를 함께 적어 두어
  누구나 직접 검산할 수 있습니다.
- **이상치 판정** — 갑자기 크게 튄 숫자를 표시하는 기준입니다. 단, **표시만 하고 값을 고치거나 빼지 않습니다.**

### 3-3. 접근 불가 소스

자료를 못 받은 출처를 기록한 곳입니다. **취소선(~~이렇게~~)이 그어져 있으면 나중에 해결됐다는 뜻**이고,
바로 뒤에 `→`로 결과가 붙습니다. 예를 들어 KRX 오픈API는 한동안 권한 오류로 막혀 있다가
2026-09-21에 열려서, 그 자리에 해결 내용과 채운 칸 수가 적혀 있습니다.

### 3-4. 진행 중 사항

아직 안 끝났거나 결정이 필요한 일의 목록입니다. 번호는 생긴 순서라 뒤죽박죽처럼 보이지만,
**취소선이 그어진 항목은 닫힌 것**이고 굵은 글씨로 남아 있는 것이 현재 열려 있는 숙제입니다.

## 4. 라운드 로그 읽는 법

한 라운드에서 무슨 일이 있었는지 시간 순으로 적혀 있습니다. **전부 읽을 필요는 없습니다.**

- **그 라운드에 어떤 기업이 추가됐는지만 알고 싶다** → 2절(기획 1팀)의 대상 표
- **데이터가 얼마나 채워졌는지** → 4절(기획 2팀)의 칸 수 표
- **왜 어떤 칸이 비었는지** → 4절의 "미확인 N칸" 또는 별도 진단 절
- **뭔가 잘못됐다가 고쳐진 이야기** → 뒤쪽 절(진단·회귀 검사·공용 코드 수정)

### 특히 볼 만한 곳: 실패와 수정 기록

이 로그의 값어치는 대부분 **틀렸던 것을 찾아낸 기록**에 있습니다. 몇 가지 예:

- `us-round14-log.md` 5절 — 미국 증권거래위원회(SEC)가 제공하는 제출 정보에 **보고 기간이 잘못 적힌 건**이 있어, 한 회사의 30개 분기가 통째로 한 칸씩 밀려 있었습니다. 찾아서 고치고, 같은 유형이 더 없는지 전체를 훑었습니다.
- `us-round16-log.md` 5·9절 — 회사가 표준이 아닌 자체 태그를 쓰거나, 숫자에 부가 정보를 붙여 공시해서 **기계가 못 읽은 칸**들입니다. 원인을 밝히고 읽는 방법을 고쳤습니다.
- `kr/logs/krx-backfill-log.md` — 2019년 주가 자료를 못 받다가 새 경로가 열려 채운 기록입니다. **소스를 바꿔 이어 붙이기 전에 겹치는 구간에서 두 소스가 같은 값을 주는지 먼저 확인**한 과정이 적혀 있습니다.

## 5. 데이터셋(CSV) 읽는 법

한 줄이 **"어느 기업의, 어느 분기의, 어떤 항목"** 하나를 뜻합니다.

| 열 | 설명 |
|---|---|
| 기업 · 종목코드 | 회사 이름과 종목 코드(국내) / 티커(미국) |
| 기간 | `2024Q3` 같은 분기 표시 |
| 기준일 | 그 값이 실제로 언제 기준인지. 분기말이 휴장일이면 직전 거래일이 들어갑니다 |
| 항목 | 매출액, 영업이익, 시가총액 등 11가지 |
| 값 | 숫자. 또는 `미확인`, `데이터 없음(...)` |
| **값구분** | **그 숫자가 어떻게 나온 것인지** (아래 설명) |
| 출처 | 공시 원문 주소. 값을 못 얻었으면 그 사유 |
| 검산 | 계산으로 만든 값의 원본 숫자 (미국 데이터셋) |

국내는 `값(원)` 열에 원 단위, 미국은 `값` + `통화`(USD) 열입니다.

### 값구분 — 숫자의 출신 성분

| 표기 | 뜻 |
|---|---|
| `공시` | 회사가 보고서에 그대로 적은 숫자 |
| `API` | 거래소·정부 시세 서비스에서 받은 숫자 |
| `계산(...)` | 공시 숫자로 계산한 값. 괄호 안이 계산 방식이고, 검산 열에 재료 숫자가 있습니다 |
| `공시(후속 보고서 비교기간)` | 그 분기 보고서에서 못 읽어, **다음 해 보고서의 비교 수치**에서 가져온 값 |
| `데이터 없음(...)` | 괄호 안이 없는 이유 (상장 전, 최초 보고기간 전 등) |
| `미확인` | 못 얻은 칸. 사유는 출처 열에 |

**`계산(...)`이 붙은 값은 회사가 그렇게 발표한 숫자가 아니라 우리가 만든 숫자입니다.**
대신 재료를 다 남겨 두었으니 직접 확인할 수 있습니다.

## 6. 자주 나오는 말

| 용어 | 뜻 |
|---|---|
| **이상치** | 직전 분기 대비 유난히 크게 변한 값. 표시만 하고 고치지 않습니다 |
| **부호 전환** | 적자↔흑자처럼 부호가 바뀐 분기. 이상치와 따로 셉니다 |
| **자체 검증** | 숫자끼리 앞뒤가 맞는지 확인. 예: `자산 = 부채 + 자본`, `종가 × 주식수 = 시가총액`. 어긋나면 값을 넣지 않고 `미확인`으로 둡니다 |
| **회귀 검사** | 코드를 고친 뒤 **과거 라운드를 전부 다시 만들어 예전 결과와 대조**하는 일. "값 변경 0"이면 고친 것이 옛 데이터를 망가뜨리지 않았다는 뜻입니다 |
| **태그** | 공시 원문에서 숫자에 붙은 이름표. 회사마다 다른 이름표를 쓰는 바람에 못 읽는 일이 생깁니다 |
| **연결 / 별도** | 자회사를 합친 재무제표가 연결입니다. 이 저장소는 **연결 기준**만 씁니다 |
| **분모** | 진행률을 잴 때의 전체 모집단. 국내는 대형주 100, 미국은 S&P500입니다 |

## 7. 이 기록이 지키는 원칙

- **확실한 미래 예측 표현을 쓰지 않습니다.** "반드시 오른다" 같은 말은 검수 단계에서 걸러집니다.
- **출처 없는 숫자를 쓰지 않습니다.** 모든 값에 원문 주소와 기준 시점이 붙습니다.
- **모르면 모른다고 적습니다.** 빈칸 대신 `미확인`과 그 사유를 남깁니다.
- **고친 기록을 지우지 않습니다.** 틀렸던 내용은 취소선으로 남기고 옆에 바로잡은 내용을 붙입니다.
