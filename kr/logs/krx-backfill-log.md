# KRX 2019년 시장데이터 백필 로그 (국내 라운드 1~5)

라운드가 아니라 전 라운드에 걸친 보정 작업이다. 요약은 `coverage-log.md`.
대상은 국내 라운드 1~5 데이터셋의 2019년 시장 3항목(분기말 종가·상장주식수·시가총액) 612칸.

## 0. 배경

공공데이터포털 주식시세 V2는 **서비스 시작일이 2020-01-02**라 2019년 4개 분기를 받을 수 없었다.
그래서 612칸이 `데이터 없음(소스 서비스 시작일 2020-01-02 이전)`으로 남아 있었다.

2026-09-20(라운드 5 0절) KRX 오픈API를 시험했을 때는 키를 등록했는데도 7개 엔드포인트가 모두
HTTP 401 `Unauthorized API Call`이었다. API별 사용 승인이 필요한 것으로 보고 보류했다.

## 1. 자동화 운영팀 — API 재확인 (2026-09-21)

`tmp_verify/krx_probe.py`

**7개 엔드포인트 모두 HTTP 200.** 키(40자)도 헤더 이름(`AUTH_KEY`)도 2026-09-20과 같고 응답만 바뀌었다.
그 사이 API 사용 승인이 난 것으로 보인다(승인 시점은 미확인).

| 엔드포인트 | 2026-09-20 | 2026-09-21 |
|---|---|---|
| `sto/stk_bydd_trd` (유가증권 일별매매) | 401 | **200** (2019-12-30 기준 916종목) |
| `sto/ksq_bydd_trd` (코스닥 일별매매) | 401 | **200** (1,408종목) |
| `sto/knx_bydd_trd` · `idx/krx_dd_trd` · `idx/kospi_dd_trd` · `sto/stk_isu_base_info` · `etp/etf_bydd_trd` | 401 | **200** |

필요한 3항목이 `sto/stk_bydd_trd` 한 곳에 다 있다: `TDD_CLSPRC`(종가) · `LIST_SHRS`(상장주식수) · `MKTCAP`(시가총액).

## 2. 소스 교차 검증 (백필 전)

소스를 바꿔 이어 붙이는 것이라, **겹치는 구간에서 두 소스가 같은 값을 주는지 먼저 확인했다.**

- 대상: 2020Q1(공공데이터포털로 이미 채운 첫 분기), 29개사 × 3항목 = **87칸**
- 결과: **87칸 전부 일치, 불일치 0.**

자체 검증(종가 × 상장주식수 = 시가총액)도 KRX 원값에서 정확히 성립한다.
예: 삼성전자 2019-12-30 종가 55,800 × 5,969,782,550주 = 333,113,866,290,000원.

스크립트 `kr/backfill_2019_krx.py`. 원본 5개 파일을 임시 폴더에 먼저 써서 대조한 뒤 반영했다.

| 합계 | 612 |

### 코스피·코스닥을 함께 조회한다

**포스코퓨처엠(003670)은 2019Q1에 코스닥이었다.** 당시 이름은 포스코케미칼이고 그해 코스피로 옮겼다.
코스피만 조회하면 이 회사의 2019Q1 3칸이 빈다. 두 시장을 모두 조회해 4개 분기를 다 채웠다
(2019-03-29 코스닥 종가 60,200 → 2019-12-30 코스피 종가 49,250).

### 못 채운 45칸 — 라벨을 바로잡았다

2019년에 상장하지 않은 회사들이다. 사유가 소스 제한이 아니라 상장 전이므로
`데이터 없음(소스 시작일)` → **`데이터 없음(상장 전)`** 으로 고치고, 출처에 종목 기본정보의 상장일을 적었다.

| 기업 | 칸 | 사유 |
|---|---:|---|
| HD현대중공업 · LG에너지솔루션 · SK스퀘어 | 각 12 | 2021~2022년 상장 |
| 한화시스템 | 9 | 2019-11-13 상장 — 2019Q4만 존재 |

## 8. 후속 — 수집기 반영과 라벨 문구 통일 (2026-09-21)

### 수집기가 2019년을 KRX에서 받는다

지금까지 `collect_round2.market_rows`는 공공데이터포털 시작일(2020-01-02) 이전 분기를 무조건
`데이터 없음(소스 시작일)`로 채웠다. 그대로 두면 **라운드 6·7에서 또 240칸이 생기고 백필을 다시 돌려야 한다.**

- 그 분기를 `backfill_2019_krx.krx_market_rows`로 받도록 바꿨다. 백필과 수집기가 **같은 함수**를 쓴다.
- 분기별 조회는 모든 종목을 한 번에 주므로 분기당 한 번만 받는다(2시장 × 4분기 = 8회).
- **검증:** 새 함수로 국내 51개사 × 2019년 4개 분기를 만들어 데이터셋과 8개 열 전부 대조 → **612칸 일치, 불일치 0.**

값 없는 칸의 기준일은 **달력 분기말**(2019-03-31 등)이다. 거래일은 값이 있는 칸에만 쓴다(기존 수집기 규칙과 같다).

### 상장 전 라벨 문구를 규격에 맞췄다

4절의 45칸은 `데이터 없음(최초 거래일 YYYY-MM-DD 이전)`으로 적었는데, 규격(coverage-log "결측 표시")과
같은 회사의 2020년 이후 칸은 **`데이터 없음(API 최초 거래일 YYYY-MM-DD 이전)`** 이다.
한 회사 시계열 안에서 문구가 둘로 갈려 있었다. 45칸의 값·출처 문구만 규격으로 고쳤다(값구분·숫자 칸 변경 0).

상장일은 두 소스가 정확히 같다(KRX 종목 기본정보 = 공공데이터포털 최초 거래일):

| 기업 | 상장일 |
|---|---|
| 한화시스템 | 2019-11-13 |
| HD현대중공업 | 2021-09-17 |
| SK스퀘어 | 2021-11-29 |
| LG에너지솔루션 | 2022-01-27 |

### 코스닥 종목 기본정보는 아직 막혀 있다

`sto/ksq_isu_base_info`(코스닥 종목 기본정보)만 **HTTP 401 `Unauthorized API Call`** 이다.
사용 승인을 받은 7개 엔드포인트에 이게 없었다. 나머지 셋(코스피 기본정보, 코스피·코스닥 일별매매)은 200이다.

- 영향: 2019년 분기에 KRX 일별매매에 없는 **코스닥** 종목은 상장일을 확인할 수 없다.
- 처리: 이 경우 추측으로 `상장 전`을 붙이지 않고 **`미확인`** 으로 둔다. 401이면 건너뛰고 수집은 계속한다.
- 지금 데이터셋에는 해당 칸이 없다(상장 전 4곳은 모두 코스피 상장).
- 대표 확인 사항: 필요하면 KRX 포털에서 `sto/ksq_isu_base_info` 사용 신청.
